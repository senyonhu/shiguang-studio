# 从旧拾光 Studio 到 RenPy 同窗版

GitHub 主分支使用新版 RenPyBridge，旧可视化编辑器和独立浏览器展示器保留在 [v0.1.1](https://github.com/senyonhu/shiguang-studio/releases/tag/v0.1.1) 历史版本及旧版备份分支。现有旧发行文件不会被新版覆盖。

| 项目 | 旧 Studio v0.1.1 | 当前 RenPy 同窗版 |
|---|---|---|
| 制作入口 | 可视化编辑器 | Codex + 31 个 MCP 工具 |
| 展示 | 浏览器 Player | RenPy Windows 程序，HTML 嵌入同一可见主窗口 |
| 作者依赖 | 原版随附 Node 运行环境 | Python 3.12、Codex、固定 RenPy SDK、同窗运行时 |
| 玩家依赖 | 旧版发布方式 | 完整解压的原生游戏包，无需作者工具 |
| 内容模型 | 旧 Studio 格式 | RenPyBridge schema 1.0 / 1.1 |
| HTML 返回剧情 | 旧实现与旧内容约定 | 明确输入、结果、分支、检查点和幂等提交 |

新版不提供旧可视化编辑器的界面，也没有现成的旧工程或旧 Player 存档转换器。不要将旧目录的 JSON 或浏览器存储直接复制进新版 `projects`。

迁移作品时保留一份完整旧工程和旧发行包，把原文、表格、图片、音频及流程说明交给 Codex；AI 提取、重新登记并生成新版工程。核对每个分支、对话、素材和小游戏，再在独立包中验收。无法自动理解的旧专有字段需要明确整理，迁移报告应列出遗漏与人工调整。

RenPyBridge 自身 schema 1.0 到 1.1 的显式迁移是另一件事：已有新版普通剧情工程可以按接口迁移后加入变量和小游戏。它不表示旧 Studio 文件或旧浏览器存档可直接兼容。
