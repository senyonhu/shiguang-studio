# 个人使用说明

RenPy Bridge 是供 Codex 调用的本地制作插件，包含制作 Skill 和31个 MCP 工具。你提供材料与剧情归属，Codex负责理解、排版、组装、预览、修改和导出。你不用填写程序参数或修改游戏代码。

当前主版本支持 Windows 同窗 HTML 小游戏。安装步骤见 [README](../README.md)，实际验证环境和剩余限制见 [VALIDATION](VALIDATION.md)；旧 Studio 的工程与存档迁移见 [迁移说明](MIGRATION_FROM_STUDIO.md)。

## 开始一次制作

完成受管安装并重启 Codex 后，先让 Codex检查插件环境，并确认它实际调用了 `get_environment` 和 `get_minigame_capabilities`。只读到说明文件不能证明工具已加载；没有同窗运行时的核心安装不能运行 HTML 小游戏。

可以直接说：

> 这里是我的 Excel 和素材文件夹。每一帧表示一次点击推进前的完整画面，请读取所有工作表，理解幕、帧、人物、配音和选项归属。位置与字号由你决定。先组装和预览关键帧，测试全部分支，通过后导出 Windows 版。

每帧写明使用的背景、人物或表情、对白、声音，以及下一帧或选项目标即可。没有人物或声音时写“无”。不用写坐标。分支用“选项1进入第几帧，选项2进入第几帧，之后回到第几帧”这样的自然语言说明。相邻帧各自完整描述，避免靠上一行猜测。

直接提取支持 XLSX、CSV、TSV、TXT、Markdown，以及 DOCX 普通段落和表格。旧 XLS、PDF、扫描图片或复杂文档需要 Codex另外转换；插件会报告不支持和未提取的内容。Excel公式没有缓存值时会明确报告，不能假装算出了结果。

## 查看与修改

Codex应展示真实 Ren’Py 截图，并说明对应的工程版本。生成了截图、编译通过或布局检查通过，都不等于已经看过画面。全部选项需要从游戏入口连续测试；单帧预览用来检查排版。

逐张审查预览后，Codex可以登记视觉基准并记录审查和更新理由。以后预览默认对照已经登记的基准，变化会产生差异图；渲染器、字体或分辨率不同时明确报告不可比较。第一次尚无基准时不声称自动比较通过，不能自动把新截图覆盖成基准。原生预览任务运行成功与视觉比较通过分别判断。画布尺寸和实际截图像素尺寸分别记录，按原生截图原像素比较，不缩放图片来凑尺寸。

修改可以直接说：

> 第四帧把人物换成微笑表情，车票稍微右移；第三帧旁白改成……，其他帧保持原样。修改前保存检查点，改完重新预览并测试。

日常局部修改保留没有指定的字段。Codex会先读当前版本再提交，避免覆盖较新的修改；重试同一次操作不会重复创建内容。

## 更新原表与恢复

> 用这个更新的 Excel重新导入同一作品。保留原来的身份和排版，列出与聊天修改冲突的地方，先让我决定冲突，再提交。

插件比较上次来源、当前作品、新材料。无冲突变化可以更新；同一字段两边不同的修改需要明确选择。不能靠重新新建十二帧来绕开冲突。你也可以让 Codex列出检查点并恢复某一版本；恢复形成新的版本，历史仍保留，之后重新验证。

受管作品保存原件、素材、内容版本、来源位置和检查点。生成的 `.rpy` 是派生产物；日常修改从自然语言和接口进行。安装升级保留作品数据，升级后核对版本和工程哈希。

若生成脚本被外部改动，后续兼容处理会列出修改、新增或缺失的文件，保存原始基准及实际改动副本并停止，避免静默吞掉改动。早期工程没有登记原始脚本哈希时会标明无法核验，不会根据现有字节补造旧基准；不会自动双向合并代码。

## 导出与已有存档

> 导出当前版本的 Windows 游戏包，在独立目录用包内程序测试全部选项、结局、图像、声音和存读档，把包与验收报告给我。

独立游戏包运行不依赖 Codex或本插件。最终包变化后需要重新验收，声音文件存在不等于已实际播放。

旧存档已经实测的范围是：同一固定 SDK、保存帧的完整状态不变、稳定身份保留、修改后续内容。修改保存帧可能重放新版画面；删除剧情或更新 SDK需要另外检查。当前固定 SDK为8.5.3.26051504。

## 出错时

告诉 Codex作品名、你刚进行的操作和看到的问题即可。它应读取真实任务状态、日志与原始材料位置，修正后重验。修改后的内容版本和最近通过路线测试的版本可能不同；任务失败不会擦掉已提交内容。

维护者继续开发时，从根目录 [START_HERE](../START_HERE.md) 和公开验证摘要核对源码、安装副本和实际任务状态。本机私人记录独立保存，不随公开源码分发。

## HTML 小游戏与剧情返回

可以让 Codex 编写或修改 HTML、CSS、JavaScript，并把整个包登记到工程。普通剧情 schema 1.0 需显式迁移到 1.1；AI 按声明的输入、结果类型和本地文件清单制作，不以未经验证的生成脚本替代工程模型。

指定进入的剧情帧、游戏输入和胜利条件，并明确胜利、失败、取消、异常与结果兜底的返回帧。分数或布尔结果通过类型检查后进入分支；变量修改使用稳定效果身份，完成后读档不会重复发奖励。

要求中途恢复时，小游戏必须调用 SDK 上报可序列化检查点。entry_restart 从入场状态重启；checkpoint 恢复上报状态。游戏显示胜利文字后还需要调用结束接口才会返回剧情。具体包与 SDK 约定见 [HTML 参考](../plugin/renpy-bridge/skills/renpy-author/references/html-minigames.md)。

窗口最小化或暂时没有可显示区域时，运行时保留当前局，恢复后继续在原窗口显示。小游戏需要声明并实现暂停能力，才能在这段时间停下倒计时；三个示例包均支持。接入其他小游戏时要实测暂停和恢复，不能假定隐藏页面会自动停止它的 JavaScript 计时器。

导出前需要实际输入和等待测试，覆盖结果、取消、异常和回到剧情；check_project 或纯 JavaScript 测试通过不能代替源工程及独立发行包的真实验收。

## 升级 SDK 与卸载

SDK按已验证版本固定。更换SDK前保留完整作品与当前包，在独立副本核对字体、脚本、画面、路线、声音和旧存档；不能把插件升级测试等同于任意SDK升级兼容。

需要卸载时直接让Codex“只卸载 RenPy Bridge，保留作品和材料”。它应通过官方插件命令移除明确身份 `renpy-bridge@renpy-bridge-personal`，只移除该插件的注册和Codex缓存。独立安装目录内的作品、SDK、历史与归档仍保留；其他插件及账号配置不属于卸载范围。移除marketplace前确认其中只有本插件；整目录删除需要另行明确指定。
