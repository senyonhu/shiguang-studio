日期：2026-09-29。状态：分析与设计草案，尚未实现新引擎。本文件记录拟议接口，不代表现有 Demo 已经支持这些能力。

后续方案已修订为：人工通过界面、外部 AI 通过 Skill/插件调用统一后台 API 制作，禁止桌面自动化；旧文中的 AI 直接写工程文件建议已被替代。实施以 [编辑器与展示器完整方案 v2](editor-player-ai-plan.md) 为准，本文件保留早期分析记录。

## 目标

制作内容时，新增章节、替换背景/立绘/音乐/视频、调整选项和同类关卡，均不修改引擎源码。全新玩法封装为独立 HTML 关卡包；引擎通过统一协议调用它。用户已明确后续剧情主要由 AI 制作，同时需要方便人修改审查，因此以结构化配置作为唯一正式数据源，以可视化审查和局部修改作为人工入口。

“不修改引擎”不等于任何新玩法都不需要开发。首次制作一种玩法仍需编写其 HTML/CSS/JavaScript；之后复用模板，通过数据制作同类关卡。引擎不自动解决剧本、教学设计或美术品质。

## 建议的产品结构

| 部分 | 责任 |
| --- | --- |
| AI 制作与人工审查工具 | AI 生成/修改配置，人工查看章节/事件列表、素材和分支，比较修改前后，表单修改、预览、工程检查、导入导出 |
| 工程内容包 | 工程清单、剧情节点、角色表、资源索引、关卡声明与文件、主题配置 |
| 剧情运行时 | 执行节点、变量与条件、选择分支、流程等待、错误恢复 |
| 舞台与媒体 | 背景、透明立绘、CG、对白、转场、BGM/音效/语音、视频 |
| HTML 关卡宿主 | 加载关卡、输入参数、接收结果、暂停恢复、进度快照、卸载清理 |
| 存档系统 | 剧情位置、变量、舞台状态、关卡快照、设置、工程与格式版本 |
| 可选服务适配器 | C 编译评测等特殊能力，按关卡需要启用 |

工程格式建议采用版本化 JSON。编辑器生成 JSON，作者不必手写；不把可执行 JavaScript 表达式塞进配置。条件采用受限的比较/逻辑结构，不使用 eval。现有 Ink 剧情可经适配或迁移进入新体系，避免让 Ink 与 JSON 同时充当全局状态的权威来源。

技术上沿用已有 Vue/TypeScript 基础，先建立通用运行时、舞台和 HTML 宿主。发布目标可以是网页和 Windows 桌面；桌面封装方案需在验证文件加载、音视频和关卡通信后确定。普通剧情和离线关卡不依赖 Python、Docker 或评测服务；C 评测单独接入。

剧情最小指令集：场景、角色显示/隐藏/表情、对白、选择、条件分支、变量更新、音乐/音效/语音、视频、等待、关卡、跳转、结束。每个节点使用稳定 ID，便于错误定位、跳转和存档迁移。

关卡节点可表达：调用 repair-circuit，传入难度/目标/允许使用的物品，接收 passed/failed/cancelled 之一，并跳转到配置中的对应剧情节点。HTML 仅返回约定的数据；剧情奖励和全局变量由宿主按配置更新，不由关卡任意修改。

## HTML 关卡协议

流程：进入剧情关卡节点 → 预加载 → HTML 发 ready → 宿主发 init → 交互 → 存进度或返回结果 → 宿主保存 → 返回剧情。

| 消息 | 方向 | 作用 |
| --- | --- | --- |
| ready | 关卡 → 宿主 | 确认加载与协议版本 |
| init | 宿主 → 关卡 | 参数、允许读取的变量、设置、历史快照 |
| checkpoint | 关卡 → 宿主 | 保存可序列化的关卡进度 |
| pause / resume | 宿主 → 关卡 | 菜单、窗口隐藏时暂停与恢复 |
| complete | 关卡 → 宿主 | 返回通过/失败/取消和约定数据 |
| error | 关卡 → 宿主 | 报告错误，保留重试或退出路径 |

所有消息包含协议版本、关卡 ID、运行实例 ID 与请求 ID。宿主验证消息来源、类型和大小，忽略旧实例、重复完成和未声明的字段。关卡切换时注销监听、释放媒体和定时器。

浏览器宿主采用 iframe 与消息通信：[iframe 文档](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)、[postMessage 文档](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)。

隔离实现应选择明确策略：关卡使用独立来源，或使用不开放同源权限的 sandbox。后者消息来源可能为 null，不能靠 origin 字符串判断身份，应结合当前 contentWindow、每次运行的握手标识或专用 MessageChannel 校验。不要给与宿主同源的任意关卡同时开放 allow-scripts 和 allow-same-origin。外部网页也不保证允许嵌入；主要支持随工程分发、遵守协议的本地 HTML 关卡包。

关卡首次加载、超时、异常退出、返回标题和读档必须有确定行为。支持 checkpoint 的关卡恢复快照；不支持的关卡明确标注“读档后重开本关”，不能假称可恢复任意 HTML 的内部状态。

C 编译评测仍由隔离服务执行，不在页面或桌面宿主直接执行学生代码。若成绩具有考试意义，宿主不能把 HTML 自报 passed 当作可信成绩，应向评测服务核验提交结果。

## 对三个痛点的具体处理

1. **反复改代码**：同类内容改配置，增加关卡不改枚举/全局流程；编辑器提供表单和事件列表。运行前检查缺图、错误节点引用、变量类型、关卡入口与协议版本，错误提示定位到章节、节点和字段。维护人员负责引擎缺陷，不把修复工作转交给作者。
2. **缺少图片资源**：资源系统与实际素材交付同时列入验收。样板章节必须带可见的背景插画、透明立绘及表情、CG、界面素材与实际音频；记录来源和使用范围。支持导入自己的 PNG/WebP/JPEG、音频和视频，逐项验证浏览器/桌面实际解码能力。拥有引擎不意味着自动拥有橙光素材的站外使用许可。
3. **关卡粗糙**：先制作一个完整的精修样板，包含目标说明、交互引导、操作反馈、递进提示、成功/失败演出和重试流程，再抽出可复用模板。HTML 带来表现自由，但关卡品质需要单独设计和试玩验证。

第一版人工界面建议采用“章节树 + 事件列表 + 属性表单 + 预览 + 修改对比”，优先完成看剧情、看素材、审查分支、改对白和从当前节点试玩。复杂的拖拽节点画布不作为第一版重点。

## AI 为主、人可修改审查的工作流

建议选择“配置优先 + 可视化审查”，而非让 AI 操作图形编辑器来制作内容。引擎执行经过校验的固定内容包，玩家游玩时默认不需要调用 AI。动态生成剧情属于独立扩展，不混入第一版。

正式工程使用版本化 JSON 与 JSON Schema；每章独立文件，节点、选项、角色、素材、关卡都有稳定 ID。数组记录事件顺序，跨文件引用只使用 ID；图片和视频存为实际文件，配置仅保存资源引用，不嵌入大段二进制数据。说明文档可用 Markdown，但不维护第二份会与 JSON 竞争的正式剧本。

AI 可以读取工程、生成新章节、修改指定节点、补充素材需求和创建 HTML 关卡。自然语言需求无需全部变成巨型配置文件；生成按章节和节点分批进行。全新玩法仍是独立插件开发，常规新关卡复用模板参数。

人工审查界面应提供：

- **剧本视图**：角色名、对白、旁白、背景/立绘缩略图、选项及去向；不要求审查者阅读 JSON。
- **分支检查**：查看某选项会进入哪里，定位缺失节点；区分结构检查通过与剧情逻辑合理，自动检查不能证明故事质量。
- **修改对比**：按稳定 ID 展示新增/删除/修改的台词、资源、分支和参数，支持接受或撤销局部修改；若修改之间有依赖，合并后必须重新校验，不能把任意碎片直接发布。
- **局部编辑**：点选对白修改文字、切换表情、更换图片、调整条件；通过同一内容读写层保存回正式 JSON，不另存一份编辑器专用剧情。
- **单段试玩**：从当前节点使用明确的测试变量启动预览；预览存档与正式存档隔离。
- **保护人工修改**：记录基础版本与内容散列，AI 补丁提交前检查版本冲突；可将节点或字段标为锁定，AI 必须报告冲突，不能静默覆盖手改内容。

内容修改流程：自然语言需求 → AI 生成草稿与改动摘要 → 格式/引用/素材/关卡协议检查 → 人看剧本、对比与预览并按需要修改 → 合并为可发布工程快照。是否每次要求人工批准由制作流程设置决定，不把运行引擎绑死在人工审批上。

校验至少包括：字段类型、唯一 ID、资源存在、跳转目标、角色/表情引用、变量声明、关卡输入输出类型、入口可达性、显式结束路径。静态发现的循环和不可达节点作为问题或提示交给作者；合法循环与复杂条件需要预览/测试判断。错误返回文件、节点 ID、字段路径和中文说明，供 AI 修复也供人定位。

第一版可由当前 AI 助手直接编辑工程文件，不必先在编辑器里接入模型账号、聊天窗口和计费系统。先保证内容协议、校验工具与预览稳定；之后任何遵守协议的 AI 都能接入。

## 实施与验收顺序

1. **底层协议**：定义工程格式、校验器、节点执行器和 HTML 关卡 SDK；用两个不同工程运行同一个引擎，证明没有固定剧情/关卡名依赖。
2. **完整运行闭环**：背景/立绘/对白 → 选择 → HTML 关卡 → 成功或失败剧情 → 存档读档；接入真实音频和一段视频，验证加载、暂停、跳过和错误恢复。
3. **AI 制作与人工审查工具**：先提供格式定义、机器可读检查结果、素材索引和预览入口，再提供剧本视图、修改对比、局部表单编辑、版本冲突提示、配置导入导出。修改现有内容并预览时，不要求作者改 TypeScript 或重编译引擎。
4. **品质样板**：用实际美术资源和完整关卡演出替换占位表现；选择一个互动关卡和一个可选 C 评测关卡验证扩展边界。
5. **迁移与发布**：旧塔章节转为工程包，旧存档先导出备份；只对明确支持的旧格式做迁移。验证离线启动、资源路径、打包和桌面运行，再提供发行包。

关键验收：新增一章和一个同类关卡只改变内容文件；遗漏资源能在发布前定位；关卡重复/延迟消息不会重复发奖励；关卡中保存退出后按声明恢复；视频失败不使剧情永久卡住；没有评测服务时仍能读剧情和运行普通关卡；发布包包含所需素材，并通过人工观看与完整流程测试。

本次交付仅为参考分析和可执行的设计约束。新引擎、编辑器、素材包与上述验收测试均尚待实现，不应把本文件作为功能已完成的证明。
