## 对本项目的核心调整

编辑器以“工程 → 章节/场景 → 有序事件”组织内容。章节和场景用于组织；实际执行顺序由事件、条件和跳转表达。素材、角色、变量、界面主题与关卡配置作为共享资源。

当前 Studio 的 StoryNode 把背景、角色和对白放在同一条节点中，类型只有 dialogue、choice、level、ending。它足够验证体验，但正式制作需要独立表达音乐、角色移动、等待、转场、条件和变量更新。保留现有引擎基础，逐项建立能力表和适配接口；编辑器不能显示引擎尚未支持的功能为已可用。

### 人工编辑工作区

| 区域 | 本项目建议 |
| --- | --- |
| 顶部 | 新建、打开、保存、撤销、检查、试玩、发布 |
| 左侧 | 上方素材浏览，下方章节/场景树；大项目可切换独立素材页 |
| 中央 | 共用展示器的舞台预览；选中对象可显示其属性 |
| 右侧 | 当前场景的事件列表，支持排序、折叠、复制、批量编辑和搜索 |
| 底部 | 插入对白、画面、音频、逻辑和关卡等命令；选中事件后显示参数 |
| 可折叠侧栏或抽屉 | AI 后台任务状态、作用范围、差异、冲突和结果；AI 需求由外部客户端输入 |

简洁视图聚合显示对白和演出摘要，详细视图展示全部事件和参数；两者只是同一数据的不同视图。切换视图保留所有事件，不能静默丢弃高级内容。

### AI 与人工共用编辑能力

每种事件定义：稳定类型名、参数规范、中文摘要、编辑表单、引用检查和运行行为。AI 接口和人工按钮都调用统一编辑服务；发布内容不依赖 AI 在线运行。

共同支持的操作包括读取工程概要、搜索和读取场景、查询素材与变量、插入事件、修改指定字段、移动一组事件、连接分支、校验和启动预览。操作都带明确对象编号与预期版本。

示例需求：“在旧塔开场加入雨声，璃从右侧走入，说完台词后出现两个选项。”AI 应查询现有素材与引擎能力，生成具体的音频、人物入场、对白与选择事件。人工看到同样的事件，可以调整音量、位置、时长和文字。缺素材或缺引擎能力时明确标记，不虚构可用资源或运行结果。

### 保存、协作和撤销

- 磁盘工程是正式保存载体；编辑器的未保存工作状态由统一编辑服务管理。
- AI 和人工都提交带基础版本的修改；版本已变化时检查受影响字段，不能用旧结果覆盖新修改。
- 将新增分支和其目标事件等互相依赖的修改作为一个事务校验与应用。
- 提供范围限制、字段锁定、自动应用或审查后应用两种流程。
- 撤销记录包含 AI 和人工操作；撤销旧任务前检查后续修改的依赖，不能盲目恢复旧工程快照。
- 保存采用临时写入后替换，并保留恢复记录；备份与版本历史独立于发布。
- 外部文件改动经过重新读取、差异检查和冲突处理后进入当前工作区。

### 引擎与展示器

编辑器试玩和独立展示器执行同一版本的事件协议。发布前验证素材、变量、跳转和关卡参数，并冻结内容版本。工程格式、运行时与关卡协议分别记录版本和兼容范围。

从中间场景试玩需要明确初始变量和舞台状态，可使用测试场景配置或受控重放；不能假定跳到某个节点就拥有前文产生的状态。HTML 关卡继续作为独立扩展，输入、结果和进度走约定协议。

这里借鉴的是职责划分、事件式制作和工程组织。文件结构无需兼容橙光，界面也不必复制其历史限制。素材和程序实现不纳入我们的发行内容。

## 第一阶段验收

1. 新建独立工程，创建两章并配置跨章跳转；关闭重开后保持一致。
2. 人工制作背景、角色、对白、音乐与选择事件，并在展示器试玩。
3. AI 通过同一编辑服务插入或修改事件，结果立即出现在人工界面。
4. AI 处理期间人工改动同一字段，返回结果不会覆盖该改动，并提供冲突定位。
5. 有依赖的一组修改整体校验；撤销可恢复该任务且保护后续独立修改。
6. 简洁和详细视图切换不丢内容。
7. 指定测试变量从某个场景试玩，并保持测试存档与正式存档分开。
8. 导出完整内容包，在独立展示器中运行；效果与编辑器预览一致。

第一阶段完成后再验证多章节、大量事件与素材下的打开、搜索、保存、加载和内存表现。安装包结构和教程都不能替代本项目自己的规模测试。
